# L1: Encoding Detection & Normalization

## 1. 목적

사용자 입력에 포함된 인코딩된 문자열(Base64, URL 인코딩, Hex escape)을 탐지하여 차단한다. 공격자가 후속 레이어의 텍스트 기반 검사를 우회하기 위해 악성 페이로드를 인코딩하는 것을 방지하는 **첫 번째 방어선** 역할.

## 판정 원칙

> **미탐(false negative)은 허용, 오탐(false positive)은 절대 불허.**
>
> 인코딩을 못 찾아서 통과시키는 것은 허용한다 — 후속 레이어에서 잡을 수 있다.
> 정상 문장을 차단하는 것은 절대 안 된다.

이 원칙은 모든 탐지 기준의 최우선 필터다. 애매하면 허용한다.

## 2. 판정 기준

**실제 디코딩을 시도하여 인코딩 존재 여부를 판단한다. 디코딩이 성공하면 차단.**

정규식 패턴 매칭이 아닌 **디코딩 시도** 방식을 사용하여 오탐을 줄인다.

### 2.1 탐지 대상 인코딩 및 탐지 방법

#### Base64

- **방법**: 입력에서 Base64 후보 부분문자열을 추출 → `base64.b64decode()` 시도 → 디코딩 성공 + 결과가 유효한 UTF-8 텍스트이면 인코딩으로 판정
- **후보 조건**: `[A-Za-z0-9+/]` 문자가 16자 이상 연속 + **패딩(`=` 또는 `==`) 필수**
- **오탐 방지 장치**:
  - 최소 16자 — 짧은 영단어가 걸리지 않도록
  - 패딩 필수 — 패딩 없는 문자열은 일반 텍스트일 가능성이 높음
  - 디코딩 결과가 유효 UTF-8이어야 함 — 바이너리 쓰레기면 허용
  - **이 조건을 모두 충족해야만 차단**. 하나라도 불충분하면 허용
- **예시**:
  - `"SGVsbG8gV29ybGQ="` (16자+, 패딩 있음, UTF-8 유효) → **차단**
  - `"aGVsbG8gd29ybGQ="` (16자+, 패딩 있음, UTF-8 유효) → **차단**
  - `"SGVsbG8="` (8자, 패딩 있음이지만 16자 미만) → **허용** (미탐 허용)
  - `"HelloWorldTest"` (패딩 없음) → **허용**
  - `"Research"` (8자 미만) → **허용**
  - `"DatabaseEngine"` (패딩 없음) → **허용**

#### URL 인코딩

- **방법**: `urllib.parse.unquote(input)` 실행 → 결과가 원본과 다르면 인코딩으로 판정
- **핵심**: 원본 ≠ 디코딩 결과 비교. `%XX` 패턴이 있어도 유효하지 않으면 unquote가 그대로 반환하므로 오탐 없음
- **오탐 검토**: 정상 문장에서 `%` 뒤에 우연히 2자리 hex가 올 수 있는가?
  - `"100%"` → unquote → `"100%"` (동일) → **허용** ✅
  - `"100%2F"` → unquote → `"100/"` (달라짐) → **차단** — `%2F`는 명백한 URL 인코딩
  - `"top 5%AC"` → unquote → 달라짐 → **차단** — 정상 문장에서 가능한 패턴인가? `%AC`는 유효한 percent-encoding이므로 차단이 적절
- **예시**:
  - `"hello%20world"` → unquote → `"hello world"` (달라짐) → **차단**
  - `"100%"` → unquote → `"100%"` (동일) → **허용**
  - `"%3Cscript%3E"` → unquote → `"<script>"` (달라짐) → **차단**

#### Hex escape (`\xXX`)

- **방법**: 입력에서 리터럴 `\xXX` 패턴(백슬래시 + x + hex 2자리)을 찾아 존재하면 차단
- **핵심**: 리터럴 문자열 `\x3C`(4글자)를 탐지. 정상 자연어 문장에 `\x` + hex 2자리가 올 확률은 극히 낮음
- **오탐 검토**: 정상 문장에 `\x` 뒤에 hex 2자리가 올 수 있는가?
  - 프로그래밍 관련 질문: `"파이썬에서 \x41은 무슨 뜻이야?"` → **차단** — 이 경우 hex escape를 설명하는 문맥이므로 차단이 적절
- **예시**:
  - `"hello \x3Cscript\x3E"` (리터럴) → **차단**
  - `"hello <script>"` → `\x` 패턴 없음 → **허용**

### 2.2 탐지하지 않는 것 (현재 범위 밖)

- `\uXXXX` (Python/JS Unicode escape) — 추후 레이어에서 처리
- `&#xXXXX;` / `&#DDDD;` (HTML 엔티티) — 추후 레이어에서 처리
- `\UXXXXXXXX` (Python 32비트 Unicode)
- 중첩(이중) 인코딩 — 1단계 디코딩만 수행
- Raw hex 문자열 (예: `68656c6c6f`)
- 패딩 없는 짧은 Base64 (미탐 허용)

## 3. 입력/출력

### 입력: `GuardrailRequest`

| 필드 | 사용 여부 | 용도 |
|------|-----------|------|
| `user_input` | O | 디코딩 시도 대상 |
| `session_id` | X | 사용 안 함 |
| `metadata` | X | 사용 안 함 |

### 출력: `LayerResult`

**허용 시:**
```python
LayerResult(
    name="L1",
    allowed=True,
    confidence=1.0,
    severity=Severity.NONE,
)
```

**차단 시:**
```python
LayerResult(
    name="L1",
    allowed=False,
    reason="base64 encoding detected at position 15",
    confidence=0.0,
    severity=Severity.HIGH,
    tags=["encoding", "base64"],
)
```

- `reason`: `"{encoding_type} encoding detected at position {N}"` 형식
- `severity`: `HIGH` (인코딩 우회 시도는 의도적 공격 가능성 높음)
- `confidence`: 차단=`0.0`, 허용=`1.0` (규칙 기반이므로 이진 판정)
- `tags`: `["encoding", "{type}"]` — type은 `base64`, `url`, `hex` 중 하나

### 복수 인코딩 감지 시

첫 번째로 발견된 인코딩 기준으로 차단. reason에는 첫 번째 감지만 보고.

### 검사 순서

URL 인코딩 → Hex escape → Base64 순으로 검사. URL/Hex는 O(n) 비용으로 빠르게 판별 가능하므로 먼저 실행하고, Base64는 후보 추출 + 디코딩 시도가 필요하므로 마지막.

## 4. 엣지 케이스

| 케이스 | 판정 | 이유 |
|--------|------|------|
| 빈 문자열 `""` | 허용 | 디코딩 시도할 내용 없음 |
| 일반 영문 `"Hello world"` | 허용 | 어떤 디코딩도 변환을 일으키지 않음 |
| `"HelloWor"` | 허용 | 16자 미만 + 패딩 없음 |
| `"Research"` | 허용 | 16자 미만 + 패딩 없음 |
| `"DatabaseEngine"` | 허용 | 패딩 없음 |
| `"안녕하세요"` | 허용 | Base64/URL/Hex 패턴 없음 |
| `"100%"` | 허용 | unquote 결과가 원본과 동일 |
| `"50%2F50"` | 차단 | unquote → `"50/50"` (달라짐) |
| `"SGVsbG8gV29ybGQ="` | 차단 | 16자+, 패딩 있음, UTF-8 유효 |
| `"SGVsbG8="` | 허용 | 16자 미만 (미탐 허용) |
| `"\x3C\x73"` (리터럴) | 차단 | 유효 hex escape 패턴 |
| 매우 긴 입력 (10,000자+) | 정상 동작 | 성능 저하 없이 동작 |
| `"data:image/png;base64,iVBOR..."` | 차단 | Base64 부분이 16자+, 패딩 있음, 디코딩 가능 |
| 대소문자 혼합 `%2f` vs `%2F` | 둘 다 차단 | unquote가 둘 다 처리 |
| 예외 발생 (비정상 입력) | 허용 | fail-open — 오탐 방지 우선 |

## 5. 보안 고려

- **fail-open**: 예외 발생 시 허용한다. 오탐 방지 원칙에 따라, 판단할 수 없으면 통과시키고 후속 레이어에 맡긴다
- **디코딩 안전성**: `base64.b64decode()`와 `urllib.parse.unquote()`는 안전한 함수. 임의 입력에 대해 예외를 던지거나 정상 반환
- **성능**: URL/Hex 검사는 O(n), Base64 후보 추출도 O(n). 디코딩 시도는 후보 개수에 비례하지만 실사용에서 후보가 많지 않음
- **우회 가능성 (미탐 허용)**:
  - 패딩 없는 짧은 Base64 → 통과됨 (의도된 미탐)
  - 공백 삽입(`S G V s b G 8=`) → 통과됨 (연속 패턴만 탐지)
  - 분산 인코딩 → 통과됨 (추후 고도화)
- **방어적 기본값**: 판단 불가 시 허용 (오탐 방지 우선)

## 6. 의존성

- **선행 레이어**: 없음 (L1은 첫 번째 레이어)
- **외부 라이브러리**: 없음 (Python 표준 라이브러리만 사용 — `base64`, `urllib.parse`, `re`)
- **LangChain**: 사용 안 함

## 7. 향후 확장

- `\uXXXX`, HTML 엔티티 등 추가 인코딩 포맷 지원
- 중첩 인코딩 탐지 (2단계+)
- 디코딩 결과를 `context.annotations`에 기록하여 후속 레이어 활용 (LayerContext 도입 시)
- 분산 인코딩 패턴 탐지 (공백/구두점으로 분리된 인코딩)
- 패딩 없는 Base64 탐지 (신뢰도 기반 판정)
- 허용 목록(allowlist) 지원 — 특정 패턴은 정상으로 간주
- `data:` URI scheme 전용 탐지 강화
